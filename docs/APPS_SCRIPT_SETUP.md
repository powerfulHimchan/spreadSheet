# 가족용 Apps Script 중계 설정

현재 앱 0.2.0은 Google 로그인 대신 **중계 웹 앱 주소 + 가족 연결키**로 연결합니다. Android OAuth 클라이언트, APK의 SHA-1 등록, 별도 서버 계약은 필요하지 않습니다. Apps Script의 기본 Google Cloud 프로젝트를 그대로 사용하세요.

## 1. 테스트 장부와 프로젝트 준비

1. PC 브라우저에서 사용할 개인 Google 계정으로 로그인합니다.
2. 원본 스프레드시트를 복사해 테스트 장부를 만듭니다. 이 계정에 장부 편집 권한이 있어야 합니다.
3. https://script.google.com/home 에서 **새 프로젝트**를 만들고 `가족 장부 중계`로 이름을 정합니다. 특정 장부에 묶이지 않은 독립 프로젝트 하나로 여러 장부를 연결할 수 있습니다.
4. 기본 `Code.gs` 내용을 지우고 저장소의 [relay/Code.gs](../relay/Code.gs) 전체를 붙여 넣고 저장합니다.
5. 왼쪽 **서비스 +**에서 **Google Sheets API**를 찾아 **추가**합니다. 기본 Cloud 프로젝트에서는 이 작업으로 API가 자동 활성화됩니다. Cloud 콘솔에서 OAuth를 직접 등록하지 않습니다.

대안으로 프로젝트 설정에서 `appsscript.json` 표시를 켜고 [relay/appsscript.json](../relay/appsscript.json)의 내용으로 설정할 수도 있습니다. 일반 사용자는 위 서비스 추가 방법만 사용하면 됩니다.

## 2. 연결키와 허용 장부 등록

1. 새 APK에서 **스프레드시트 연결 → 새 연결키 생성 → 연결키 복사**를 누릅니다. 아직 주소가 없어도 생성·복사는 가능합니다. 이 키를 따로 보관하세요. 연결 완료 전 대화상자를 닫으면 자동 저장되지 않습니다.
2. Apps Script 왼쪽 **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**에서 아래 두 항목을 저장합니다.

| 속성 | 값 |
|---|---|
| `FAMILY_KEY` | 앱에서 생성한 연결키 그대로 |
| `ALLOWED_SPREADSHEET_IDS` | 테스트 장부 ID. 여러 개는 쉼표로 구분 |

예를 들어 `https://docs.google.com/spreadsheets/d/여기가_ID/edit`에서 `/d/` 다음부터 `/edit` 앞까지가 장부 ID입니다. URL 전체를 속성에 넣지 않습니다. 실제 장부 ID나 연결키를 소스 코드·채팅·공개 저장소에 넣지 마세요.

## 3. 소유자 권한 승인

1. 코드 편집기로 돌아가 상단 함수 목록에서 `checkConfiguration`을 선택하고 **실행**합니다.
2. 권한 검토에서 프로젝트를 만든 계정을 선택하고 시트 접근을 승인합니다.
3. 자신이 붙여 넣은 코드임을 확인한 뒤, 미검증 앱 안내가 나오면 **고급 → 해당 프로젝트로 이동**으로 진행할 수 있습니다. 소유자가 처음 한 번 승인하는 과정입니다.
4. 실행 기록이 완료인지 확인합니다. 키나 허용 ID 설정이 잘못되어 있으면 해당 오류를 먼저 수정합니다.

## 4. 웹 앱 배포

1. 우측 상단 **배포 → 새 배포 → 유형 선택(톱니바퀴) → 웹 앱**.
2. **실행할 사용자: 나**.
3. **액세스 권한: 모든 사용자**(Google 로그인 없이 접근 가능한 옵션).
4. **배포**를 누르고 `https://script.google.com/macros/s/…/exec` 웹 앱 URL을 복사합니다. 배포 ID나 `/dev` 주소를 사용하지 않습니다.

계정 정책에 따라 로그인 없는 `모든 사용자` 옵션이 없을 수 있습니다. 회사·학교 계정 대신 개인 계정으로 확인하세요. 이 옵션이 없는 계정에서는 현재의 로그인 없는 연결 방식을 사용할 수 없습니다.

중계 주소를 브라우저에서 열면 `FamilyLedger relay`와 프로토콜 번호만 표시됩니다. 이것은 접속 확인이며 시트 읽기·쓰기 검증은 아닙니다. 키 없는 요청으로 장부 데이터는 반환하지 않습니다.

## 5. 앱 연결 및 가족 공유

1. 앱의 **스프레드시트 연결**에 **중계 웹 앱 주소**, **동일한 가족 연결키**, **테스트 장부 URL**을 입력합니다.
2. **연결하고 불러오기**를 누르고 탭·표 영역·컬럼 역할을 확인합니다.
3. 테스트 장부에서 조회·안전한 편집 설정·추가·수정·논리 삭제를 확인합니다. 다른 가족의 수정 이후 오래된 화면에서 저장하면 충돌이 차단되는지도 확인합니다.
4. 정상 동작하면 `ALLOWED_SPREADSHEET_IDS`에 실제 장부 ID를 추가합니다. 스크립트 속성 변경은 코드 재배포 없이 적용됩니다.
5. 가족 휴대폰에도 새 APK를 설치하고 같은 중계 주소·연결키·장부 URL을 입력합니다. 가족은 앱에서 Google 로그인할 필요가 없습니다. 각 기기의 표 매핑은 별도로 저장됩니다.

## 관리

- 시트 자체의 공개 공유 설정을 바꿀 필요는 없습니다. 웹 앱은 소유자 권한으로 실행되며, 연결키를 아는 사람은 허용 목록의 모든 장부에 접근할 수 있습니다. 키를 비밀번호처럼 가족끼리만 공유하세요. 가족별 권한 분리는 현재 범위에 포함하지 않습니다.
- 키를 바꾸려면 `FAMILY_KEY` 속성을 교체하고 가족 앱에도 새 키를 입력합니다. 앱에서 키만 새로 생성하면 연결되지 않습니다.
- 접근을 중단하려면 **배포 관리**에서 해당 배포를 보관 처리하거나, 가족 연결키를 교체하세요.
- `Code.gs` 수정 후에는 **배포 → 배포 관리 → 수정 → 새 버전 → 배포**로 기존 URL을 갱신하세요. 에디터에서 저장만 하면 기존 `/exec`는 갱신되지 않습니다.
- 기본 할당량·소유자의 시트 권한·인터넷 연결에 영향을 받습니다. 스크립트 잠금은 중계를 통한 가족 저장을 직렬화합니다. Google Sheets 화면이나 다른 외부 앱의 저장까지 잠그지는 못합니다. 원본을 직접 편집하는 작업과 앱 저장이 정확히 겹치는 경쟁은 완전히 제거하지 못합니다.
- 한 앱에는 중계 서버 설정 하나를 저장하며, 해당 중계의 허용 목록에 등록된 여러 장부를 연결할 수 있습니다. 다른 중계로 설정을 바꾼 경우 기존 장부의 접근 권한을 다시 확인해야 합니다.
- 이 APK는 테스트용 debug 빌드입니다. 빌드마다 디버그 서명이 다르면 기존 테스트 앱 위에 설치되지 않을 수 있습니다. 이런 경우 기기의 연결·캐시를 보존할 방법을 먼저 확인하고 설치해야 합니다. 정식 배포에는 소유자가 관리하는 고정 서명이 필요합니다.

## 검증 범위

중계 로직은 Node의 가상 Sheets 서비스로 인증·허용 목록·충돌·수식 보호·잠금·요청 제한을 검사합니다. Android 앱은 CI에서 핵심 단위 테스트·lint·APK 빌드를 검사합니다. 실제 Google 계정의 권한 승인·배포·실제 시트 읽기·쓰기·기기 화면 흐름은 소유자의 초기 설정 후 검증해야 합니다. 자동 검사가 실제 계정 연동을 대신하지 않습니다.
